# Languages

[← docs index](README.md)

The languages your site speaks are the ones `MESSAGES` imports, at the top
of `profile.config.ts`. That line is the whole setup.

```ts
import en from "./src/i18n/messages/en.ts";
import ru from "./src/i18n/messages/ru.ts";

export const MESSAGES = { en, ru };   // English-only? delete the ru line.
```

The first one is the default: served at `/` and `/cv.html`, with the others
at `/<locale>/cv.html`. The language chip cycles through them in this
order. With a single language the chip and the `lang` command don't
appear.

Every text field in the config then wants each language you listed, and
TypeScript names any you've missed — a half-translated site doesn't build.
The same works in reverse: drop a language and it names every field still
carrying it.

The jokes are adapted, not translated word for word: puns get a native
equivalent where one exists, while the `kubectl`/`terraform`/`sudo`
parodies and the `[  OK  ]` boot tags stay as they are, so the output still
reads as terminal output.

## Adding a language

1. A new file in `src/i18n/messages/`, copied from `en.ts` and translated.
   `en.ts` is the schema, so a missing key is a compile error.
2. Its import and entry in `MESSAGES`.

`npm test` then checks what types can't: every `{placeholder}` present,
scripted sequences the same length, inline markup matching, and that the
language names itself in its own `lang.set` line. It checks every file in
the folder, imported or not.
